# بسته آماده‌سازی بک‌اند MH Flow

این پوشه قرارداد و تصمیم‌های پایه برای شروع بک‌اند است؛ **خود بک‌اند در این مرحله ساخته یا اجرا نشده است**. فرانت‌اند فعلی همچنان نمایشی است و هیچ وضعیت اشتراک یا پرداختی را معتبر تلقی نمی‌کند.

## تصمیم‌های قطعی فعلی
- محصول: MH Flow
- ارز نمایش و تسویه داخلی: تومان (IRR باید در لایه ذخیره‌سازی/درگاه به‌صورت واحد صریح مدیریت شود؛ مبلغ‌ها هرگز با عدد بدون واحد جابه‌جا نشوند.)
- پرداخت: درگاه داخلی ایران
- ارائه‌دهنده درگاه: هنوز انتخاب نشده (`other`). کد سرور باید از رابط `PaymentProvider` استفاده کند و به نام یک درگاه خاص وابسته نباشد.
- پلن‌ها: Free، Pro و Team
- وظایف شخصی مستقل از Workspace و غیرقابل مشاهده برای اعضای تیم
- نقش‌های پایه Workspace: Owner، Admin، Member
- پایگاه داده هدف: PostgreSQL
- API نسخه‌دار: `/api/v1`

## پیش‌نیازهای اجرایی پیش از اتصال پرداخت
1. انتخاب شرکت/درگاه دارای قرارداد معتبر و دریافت مستندات رسمی، Merchant ID و کلیدهای محیط آزمایشی/عملیاتی.
2. تعیین قیمت قطعی Pro و Team، دوره‌های ماهانه/سالانه، سیاست تمدید، لغو، بازپرداخت و مالیات.
3. بررسی الزامات حقوقی/مالیاتی و احراز هویت پذیرنده. این موارد را نمی‌توان از انتخاب «پرداخت داخلی» استنتاج کرد.
4. پیاده‌سازی API و دیتابیس، سپس اتصال UI به API واقعی.

## اصول پرداخت
- مبلغ سمت سرور از کاتالوگ پلن محاسبه شود؛ مبلغ ارسال‌شده از مرورگر قابل اعتماد نیست.
- ساخت Payment و Order در تراکنش دیتابیس انجام شود.
- مرورگر فقط به آدرس پرداخت هدایت شود؛ بازگشت مرورگر به سایت به‌تنهایی اثبات پرداخت نیست.
- callback/webhook با API استعلام رسمی درگاه تأیید شود.
- شناسه تراکنش/مرجع درگاه unique باشد و callback تکراری idempotent پردازش شود.
- فقط پس از تأیید معتبر درگاه، اشتراک فعال یا تمدید شود.
- اسرار درگاه فقط در Secret Manager یا متغیر محیطی سرور نگهداری شوند؛ هرگز در Vite env با پیشوند `VITE_` قرار نگیرند.
- لغو تمدید خودکار با انقضای اشتراک تفاوت دارد؛ وضعیت و تاریخ دسترسی صریح ذخیره شوند.

## ترتیب پیشنهادی پیاده‌سازی
1. Auth، session امن، کاربران و migrationهای PostgreSQL.
2. کاتالوگ پلن‌ها، entitlementها و endpoint وضعیت اشتراک.
3. Workspace، عضویت‌ها، دعوت‌ها و مجوزهای سمت سرور.
4. پروژه‌ها و وظایف تیمی؛ جداسازی قطعی از وظایف شخصی.
5. PaymentProvider adapter و محیط Sandbox درگاه انتخاب‌شده.
6. پرداخت واقعی، callback verify، تمدید، لغو و سوابق مالی.
7. پیام‌رسانی Realtime، فایل‌ها، اعلان‌ها و گزارش ممیزی.
8. اتصال فرانت‌اند، تست امنیتی و انتشار مرحله‌ای.

## فایل‌ها
- `API-CONTRACT-fa.md`: مسیرها و شکل پیشنهادی API.
- `PAYMENTS-fa.md`: چرخه پرداخت و قرارداد adapter مستقل از ارائه‌دهنده.
- `../../db/migrations/001_core_schema.sql`: طرح اولیه جداول PostgreSQL؛ پیش از production باید بازبینی و به migrationهای کوچک‌تر تقسیم شود.

## هشدار مهم
Schema و قرارداد API، نقطه شروع مهندسی‌اند نه جایگزین بازبینی امنیتی، تست بار، سیاست پشتیبان‌گیری، مدیریت اسرار و بررسی حقوقی. هیچ endpoint یا درگاهی در این بسته عملیاتی نیست.
